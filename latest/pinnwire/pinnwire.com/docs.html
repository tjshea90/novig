PinnWire API Documentation

This page is the full reference for PinnWire's real-time Pinnacle odds API: REST endpoints, a queryable drops buffer, push-based SSE drop alerts and a raw WebSocket. The REST endpoints are testable right now with the public demo key (key=demo) — no signup; SSE and WebSocket need a plan key. The same content ships as plain text for LLM and agent use (llms-full.txt).

Real-time live and prematch Pinnacle odds — REST snapshots, a queryable drops buffer, push-based SSE drop alerts, and a raw Real-time WebSocket. REST and the SSE drop streams deliver decimal prices; the raw WebSocket is a verbatim feed passthrough, so its price fields keep the feed's native odds format. The /kit/v1/* endpoints mirror common third-party Pinnacle API formats: swap the base URL and key in an existing client and it should just work.

Need instant suspensions or prices? Use WebSocket. REST only updates when you request again.

Base URL: https://pinnwire.com. All responses are JSON.

Authentication

Your API key is your only credential — no username, no password. Get a free trial key in seconds on the homepage (no card), or try everything right now with the public demo key: literally key=demo (10 req/min, 50/day, REST only).

Pass the key either way:

x-api-key: YOUR_KEYheader — recommended
?key=YOUR_KEYquery parameter — handy for curl and browsers

Failure → HTTP 401 {"error":"invalid_key"}. SSE needs a plan with drop alerts (Stream, Pro + Drops, Scale). WebSocket needs the WS add-on.

GET /kit/v1/details

One event by ID: ?event_id=N → { events: [<one event>] }. A special's ID returns the special shape directly — no flag needed.

GET /kit/v1/prematch/fixtures

Every upcoming fixture for a sport with full markets. Equivalent to /kit/v1/markets?event_type=prematch. Params: sport_id (required; all for every sport), since, include_specials, include_alt_units.

curl "https://pinnwire.com/kit/v1/prematch/fixtures?sport_id=1&include_specials=1&key=YOUR_KEY"

GET /kit/v1/prematch/markets

Player props & specials

Special-market events — Player Props, Team Props, Exact Scores, futures — ride alongside the main fixtures. Off by default; opt in with include_specials on /kit/v1/markets or /kit/v1/prematch/fixtures: 1 adds them as flat extra rows, nested groups them under each parent event's specials array.

{ "event_id": 1634672697, "sport_id": 1,
  "special": "Anytime Goalscorer", "special_category": "Player Props",
  "special_units": "Regular", "parent_id": 1634444746,
  "special_markets": { "num_0": [ { "type": "moneyline", "key": "s;0;m", "side": null,
      "max_risk": 100, "prices": [
        { "name": "John Striker", "participant_id": 9001, "points": null, "price": 3.5 } ] } ] } }

Decimal prices, named outcomes. Fetch a single special via /kit/v1/details?event_id=<special_id> — no flag needed. Qualifying special-market price falls appear on /api/drops and the applicable SSE drop stream with participant_name.

nvp is the no-vig fair price — (to / nvp) − 1 estimates your edge. Special-market drops carry participant_name. (The SSE streams use from_price/to_price/sect/outcome — that matches the wire format of comparable SSE feeds.)

SSE /odds-drop (live)

Push stream of live odds drops. One connection, sub-second from price move to your code. Plans: Stream, Pro + Drops, Scale.

curl -N "https://pinnwire.com/odds-drop?key=YOUR_KEY&min_drop=5"

data: {"type":"connected","id":"…"}
data: [{"home":"…","away":"…","sect":"Spread","from_price":2.24,
        "to_price":2.21,"drop_pct":1.34,"nvp":2.385,"is_live":true,…}]

Frames are JSON arrays of drop objects (same shape as /api/drops). min_drop=N overrides the default 5% threshold per connection — floor 1%, no upper cap. Keep-alive comments (:ka) every 25 s — ignore them.

SSE /odds-drop-prematch

Identical to /odds-drop, prematch feed only. Prematch lines move slowly — a 90-second sample may surface zero drops; that's normal.

recheck=N (prematch only): stable-price filter. Holds each drop N seconds, re-reads the current price, and only emits if the drop still passes your threshold against the original from_price. Bounced-back prices are silently suppressed; emitted alerts include rechecked_ms. Ignored on the live endpoint.

# Only emit if a ≥7% drop is still ≥7% after 30s
curl -N "https://pinnwire.com/odds-drop-prematch?key=YOUR_KEY&recheck=30&min_drop=7"

Real-time WebSocket +$89/mo add-on

Raw feed passthrough — every frame forwarded verbatim in a thin envelope. This is the full state stream (opens, closes, every reprice), not the drop alerts. Much higher volume.

wss://pinnwire.com/ws?key=YOUR_KEY     (also accepted: /ws/feed)

On connect: {"type":"connected","events_in_store":N}. Subscribe within 10 s or the socket is closed — by sport (every event in that sport) and/or by specific event IDs (filtered, max 200 per stream):

{ "type": "subscribe", "streams": ["live","prematch"],
  "sport_ids": [1, 2], "event_ids": [1631005165] }
{ "type": "unsubscribe", "streams": ["live"], "sport_ids": [2] }
{ "type": "pong" }   // reply to the server's ping

Each subscription is acked (subscribed/unsubscribed) and answered with a snapshot of the matching events (large baselines are split into chunks tagged seq/final; a single-frame snapshot has neither). Then continuous frames of type live ({topic, op, rec}, op = add/upd/del), prematch_ws, prematch_matchups, prematch_markets — only for what you subscribed to. A frame matches if its sport is in your sport subs or its event ID is in your event subs. Deleted events are auto-removed from your event subs.

Heartbeat: server sends {"type":"ping","ts":…,"buffered_max_bytes":N} every 30 s — reply {"type":"pong"} or be closed after ~75 s (1001 "stale"). buffered_max_bytes is your send-backlog high-water mark since the last ping — use it to measure headroom.

CloseReasonMeaning
1001evicted by newer connectionOne connection per key — a second one evicts the first
1001staleNo pong for ~75 s
1008no subscribe / invalid key / plan lacks wsFix and reconnect
1011deregistered: slow_consumerClient fell >32 MB behind — reconnect immediately

Compression: permessage-deflate is negotiated per connection — your client decides. ~5× smaller frames (helps thin/long-haul links), but adds a latency tail during update bursts. Far from the server → enable; fat stable pipe → off. Node ws: {perMessageDeflate: true}; Python websockets: on by default; browsers: automatic.

Errors: {"type":"error","code":"invalid_subscribe"|"event_id_cap"}. Merge rules: key your book by rec.id + market key (m.key, else type|period|side|points) — never team names. Dedupe on markets[i].version, not rec.version. m.status present and not "open" closes a market — guard on presence (m.status != null), because an absent status is not a close, and apply the close before the version dedupe so a close cannot be discarded as an unchanged re-send. These merge rules are for the raw WebSocket; REST returns the book already merged, where a closed market is absent from markets[]. Live topic channel ld is the real price; dz is a volatility signal, not a second price. Reconnects re-sync from the snapshot — server keeps no session state.

GET /v1/health · GET /ping

/v1/health?key=… → {"status":"ok","generated_at":"2026-09-15T12:00:00.000Z","last_odds_update_seconds_ago":2,"events_in_store":N,"upstream":{…},"ws_clients":N}. generated_at is the response time; last_odds_update_seconds_ago is the age of the newest odds frame. /ping is public, returns ok — for load balancers and uptime monitors.

POST /signup

Protected browser signup handler used by the homepage free-key box. It requires a fresh Cloudflare Turnstile token, then emails the key (the key is never returned in the response). For safety, repeat sends have a cooldown and trial-email delivery has persistent global limits. Use the homepage instead of calling this route directly.
