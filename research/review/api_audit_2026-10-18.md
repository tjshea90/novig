## Findings and what was done
1. **SX prices looked 32 min old while the socket was live (TCL119): FIXED.** `SxBetClient.books` returned the socket's board as-is, and an unchanged market kept the time it was first read, so the scan's
   freshness rules saw minutes-old quotes. SX's `best_odds_v3:global` channel pushes every change, so on a connection whose subscription was acknowledged a market with no push is unchanged: it is now
   current as of the read (`SxBetStream.currentAt`, the same rule as Kalshi's `trusted`). A book laid before the current subscription keeps its own age. Test: `SxBetStreamTest`.
2. **BoltOdds connection budget could be exceeded: FIXED.** The plan allows 3 connections; the runner holds 2 (lines + props) and the phone's sockets followed the same shared switch, so a phone with
   BoltOdds on could open 2 more (4 > 3). Now the phone holds no BoltOdds, Kalshi or SX socket while the engine scans and live runs on GitHub (`ScanSettings.phoneSockets`), and in Phone mode the runner
   closes its own (`CloudEngine.forCloud`, `CloudSources.applySockets`, within 3 s). Test: `LiveBoardTest`.
3. **Kalshi keeps markets it no longer wants subscribed (31 of 9,082): noted, not changed.** `KalshiStream.syncSubscriptions` only adds; removing needs `update_subscription delete_markets` per sid.
   The waste is 0.3% of the pushes, so it is not worth the risk to the subscription bookkeeping. Revisit if the gap ever grows past ~10%.
4. **SX is used to its potential for the scan (REST markets + socket books + socket scores) and for live (the live taker's `pinnWebsite.sx` feed).** The live taker is off in Tj's settings (`pinnLive`
   false), so SX only feeds the scan today. Live light (on, REAL) uses Novig's live books + ESPN scores + BoltOdds' soft-book average as its second opinion.
5. **Kalshi's key is used as allowed (read + stream only; no order path exists).** **BoltOdds** is on no `ApiChain` (free memory read), as designed.
