# The scheduled Vigilant review (Tj, 2026-10-15, permanent until he changes it)

Tj: "I want Claude to do scheduled diagnostics and improvements in vigilant. I want it to log and review all scanned positive EV bets and look for patterns and what really is profitable. Can Claude also install the updated code automatically onto GitHub so I notice improvements on my phone without doing anything myself?" (TASKS.md TCL18)

A fresh Claude session runs this once a day. GitHub has already done the crunching for free: `.github/workflows/review-digest.yml` (12:20 UTC) runs the app's own scan-study report over every bet the phone logged (`phone-data` branch: `phone/study`, `phone/bets`) and appends it to the `review-digest` branch (`latest.txt`, `digest/<date>.txt`). **Read the digest; do not re-crunch the journals** (that is the usage this routine exists to save).

## Each run, in this order (save as you go: `bash tools/ckpt.sh "did" "next"` after every step; you can be cut off at any moment)
1. `bash tools/install-hooks.sh` if the session briefing did not show. Read CHECKPOINT.md and the open items of TASKS.md; if another session is mid-change, finish that first.
2. `git fetch origin review-digest cloud-feed phone-data`. Read `git show origin/review-digest:latest.txt` (READ ME, SUMMARY, SPLITS, then the placed-bets table). If it is older than 36 h, the workflow failed: read its run (`mcp__github__actions_list` `review-digest.yml`, `get_job_logs`), fix it, re-dispatch it once.
3. **Engine health** (`cloud-feed` `status.json` and `engine-log.txt` through the contents API, never raw.githubusercontent.com): heartbeat age, `novigRoute`, scan time, base Novig prices read vs hot re-reads, `problem`, bids. Anything wrong and fixable is a fix (class A below).
4. **Patterns.** From SUMMARY and SPLITS: which groups (league, kind, lead time, books agree, star rating, fair age, price band, source) have CLV and ROI that are positive AND supported (n 200+ with a close for CLV; the ± counts games, not bets; say the t-statistics; ROI over a few hundred bets is noise). Compare with the previous digest (`git show origin/review-digest:digest/<yesterday>.txt`): did anything change, did last week's finding hold? Write the finding to `research/review/<date>.md` (short: what held, what did not, numbers, n) and one line in `research/lab/NOTES.md`. A finding that rests on thin data says so.
5. **Improvements.** Pick at most 2 per run. Class decides what you may do alone:
   - **A. Ship without asking** (gate: `bash ship.sh`, the full test floor; then `release.yml`, `record-release.sh`): bug fixes, speed, crashes, diagnostics and report additions, the GitHub engine's plumbing, anything that does NOT change which bets or bids are listed, placed or posted, how a fair line is made, a stake, a limit, a threshold, a tier or a default. The engine takes main's code at its next handover or restart by itself.
   - **B. Needs Tj's word first**: any change to bet or bid selection, fair-line math, stakes, limits, EV or star thresholds, tiers, haircuts, switches' defaults, what the auto-bet or bid desk may do. Do not implement. Write it in TASKS.md under a heading `NEEDS TJ` with the evidence (n, ROI, CLV, ± and what would change), so the next session shows it to him. (CLAUDE.md, scan study: "ask him before changing any rule it suggests".)
   - **C. Never**: put a key in a file, open Pinnodds/BoltOdds/Kalshi sockets, touch `mgm/`, change the signing keystore or applicationId, place or cancel an order, rewrite `phone-data`, disable a workflow to hide a failure.
6. A change that touches the phone app is released as an APK (the phone installs it: see "Delivery" below); a change that is engine-only reaches the runner by itself. Say which in the checkpoint.
7. Finish with `bash tools/ckpt.sh` naming what was found, what shipped, what waits for Tj. If you ran short of budget, the checkpoint comes first, the next improvement second.

## Delivery to the phone (TCL18d)
The engine runs from `main` on GitHub's runners, so a pushed engine change is live at the engine's next handover or restart. The phone's APK is different: Android will not install a sideloaded APK without the phone's own installer. An in-app updater (Settings › Updates) is TASKS.md TCL18d; until it exists and Tj has allowed it, a release is a link he taps.
