Tj: "allow me to send my novig key and boltodds key to GitHub for rapid scanning. I want the GitHub engine to still rank apis by measured quality and freshness." (TASKS.md TCL13; it is the word TCL11 waited for.)

| | Decision | Why |
|---|---|---|

## How it works
- Phone: Settings › Cloud scan › **Send a Novig read-only key** (one tap, makes ONE key named "Vigilant cloud engine" on the Vigilant subaccount, then sends it with the other keys); once made, the key is kept sealed (`cloud_novig_key.json`, excluded from backups) and goes again with every automatic key send. **Remove it** deletes both secrets and forgets the key (it stays registered in Novig, read-only: revoke it there if you like). BoltOdds goes with "Send my API keys" like the others.
- Engine: `CloudMain` reads the two Novig secrets (`CloudKeys.rawEnv`: a PEM is never split on its line breaks), builds `CloudNovig` (signed client + `NovigStream`), and `configure`s it each scan from the phone's Novig switches (`novigSocket`, `novigBbo`, `novigKeepOpen`, `novigCompress`: now FETCH settings in `CloudScanKey`; the orders channel is never asked for). `CloudSources` builds BoltOdds when `gates.useBoltOdds` and the key exists; its socket switch off = REST snapshot; BoltOdds off = sockets closed.
- Status (`status.json` on `cloud-feed`): `novigRoute` ("Novig read-only key active: 14 reads a second, websocket on" / "public routes: the read key was refused (451 ...)" / "public routes only (no Novig key was sent ...)"), `ranking`, `sources`, `scanNote`.
