## 1. Basics
- Base `https://api.sharpapi.io/api/v1` (never `sharpapi.io`). Key in `X-API-Key` (or Bearer, or `?api_key=`); keys look like `sk_live_...`. JSON, snake_case, RFC 3339 times.
- **Sharp plan:** 25 books chosen on the dashboard (no `sportsbook=` filter = those), **1,000 requests a minute**, no data delay (`X-Data-Delay: 0`), Pinnacle + the sharp books (Pinnacle, Circa, SBOBET, 1xBet, Bookmaker, Betfair, ProphetX), EV / middles / low hold / splits, closing lines (`/odds/closing`). NOT on Sharp: streaming (SSE/WebSocket, a $99 add-on Tj does not have), game state (its own add-on), history / historical CLV / futures / injuries (Enterprise).
- Headers on every answer: `X-RateLimit-Limit/Remaining/Reset`, `X-Data-Delay`, `X-Request-Id`, `ETag` (send `If-None-Match` for a free 304), `X-Response-Cache`.
- Errors: `{"error":{"code","message",...}}`; the HTTP status is the truth. 401 `missing_api_key|invalid_api_key|expired_api_key|disabled_api_key` (the key is refused), 403 `tier_restricted|book_not_selected`, 400 `validation_error|invalid_filter|offset_too_large|cursor_expired`, 410 `gone|unknown_endpoint`, 429 `rate_limited` (`Retry-After` seconds; `retry_after` is Unix MS) and `concurrent_request_cap` (too many in flight), 502 `upstream_error`, 503 `book_unavailable|not_ready|service_unavailable`.
- Connection reuse matters: a fresh TLS handshake costs 150-200 ms, the server answers in ~40-50 ms. One OkHttp client for everything.

## 2. Odds (the data Vigilant uses)
- `GET /odds`: rows `{id, sportsbook, event_id, sport, league, home_team, away_team, market_type, selection, selection_type, team_side, odds_american, odds_decimal, odds_probability, line, is_main_line, is_alternate_line, event_start_time, timestamp, is_live, is_active, is_stale_pregame_price, market_segment, player_name, stat_category, max_bet, size_currency, best_bid_liquidity, total_liquidity, ...}`. Filters: `sportsbook, sport, league, market (aliases main|spread|total|props, or exact market_type), event_id, player_name, is_live, is_main_line, limit (≤200), cursor`. Ordered by start time. Pages with `next_cursor` (offset ≤ 500). An empty page carries `meta.store.reason` (`warming|store_empty` = retry, `no_match` = real).
- **`timestamp` is when SharpAPI last delivered the row (every ingest cycle), NOT when the price last moved.** There is no price-change time any more. The store refreshes about every 15 s; a row whose `timestamp` stops advancing is the stale signal.
- Collection latency (April 2026, theirs): **Pinnacle by MQTT push p50 0.8 s, p95 ~4 s; Circa by WebSocket push, Bet365 fast poll (~Pinnacle)**; DraftKings poll p50 8 s / p95 21 s, FanDuel 2.7 / 5.9 s; SBOBET, 1xBet polled like DK/FD. **Novig and Polymarket are pre-match only there** (no live).
- `GET /odds/delta?since=` (required; ≤10 min back for removals): the rows changed since `since` + `removed[]` (`{id, sportsbook, removed_at, was_live, boundary}`), `limit` ≤ 500, page with `offset=next_offset` keeping `since`; on the terminal page (`has_more:false`) take `meta.server_time` as the next `since`. `next_offset:null` while `has_more` or `overflow` is true = re-baseline from `/odds`. `is_active:false` = suspended in place (do not price it). Odds ids are deterministic (a market that comes back has the same id).
- Market names: `moneyline` (also matches `moneyline_3-way`), `point_spread`, `run_line`, `puck_line`, `total_points|total_runs|total_goals`, `team_total`, period prefixes `1st_half_*`, `1st_5_innings_*` (`market_segment` says which), player props `player_<stat>` with `player_name` + `selection_type over|under` + `line` (key on `(market_type, player_name, selection_type, line)`; `selection` is the side, never the player). Selection types `home|away|over|under|yes|no|draw|...`.
- Event ids are canonical across books: `{league}_{teamA}_{teamB}_{YYYY-MM-DD}_b{0-3}` (teams alphabetical, 6-hour bucket, ET for US leagues), `_g{N}` for a doubleheader's second game.
- Liquidity: `max_bet` is a sportsbook's limit (Pinnacle, Circa, SBOBET; USD) or an exchange's size at the best price (`size_currency`, GBP on Betfair).
- Also: `/odds/best`, `/odds/comparison`, `POST /odds/batch` (≤50 events on Sharp): other views of the same store; Vigilant does not need them (it keeps the store itself).

## 3. Other endpoints
- `GET /odds/closing?event_id=` (Pro+): every book's price at the moment it turned the event live (`capture_trigger` transition > kickoff > others), with `no_vig_probability` (power devig) and `closing_probability`; kept 48 h.
- `GET /opportunities/ev` (Pro+): SharpAPI's own +EV list (`sportsbook=novig`), Pinnacle (or `devig_book`) devigged POWER, with `confidence`, `kelly_percent`, `cross_ref_count`, `quality_tier` A/B/C, `warnings`, `oldest_odds_age_seconds`, `est_correction_s`. Also `/opportunities/arbitrage|middles|low_hold`.
- `GET /splits` (Pro+): public betting percentages.
- `GET /account` (tier, `rate_limit.requests_per_minute`, `max_books`, `features`), `GET /account/usage` (`requests_today` since 00:00 UTC, the minute's window), `GET /health` (public: `status ok|degraded|starting|down`, `newest_odds_age_s`).
- `/events`, `/events/:id`, `/sports`, `/leagues` (slugs: `nfl, ncaaf, nba, ncaab, wnba, mlb, nhl, atp, wta`, soccer like `england_-_premier_league`), `/sportsbooks` (`is_sharp`, `has_live_odds`, `requires_tier`, `last_update`), `/markets`, `/teams`, `/deeplink/:id`.

## 4. How Vigilant uses it (built 2026-10-21, TASKS.md SA)
See the code headers in `data/.../sharpapi/` for the current truth.
- **The engine keeps a copy of the whole store** (`SharpApiFeed`): each league the scan asks for is read once by cursor pages (`/odds?league=..&market=..&is_live=false|true`), then **`/odds/delta` every 2 s** (all loaded leagues) keeps it current, so a scan reads it from memory (free, seconds old) the way it reads BoltOdds' socket board. A delta that cannot be drained re-reads the leagues. Pacing: at most 900 requests a minute (`SharpApiClient` gate), 4 in flight.
- **Fair odds** (`SharpApiSource`, ids `sharpapi` / `sharpapi-props`): every book but the ones Vigilant reads itself or that are not prices (Novig, Kalshi, Polymarket, SX Bet, the DFS apps). Pinnacle, Circa, Bookmaker, Betfair, ProphetX, SBOBET become sharp books Vigilant did not have.
- **Live:** `SharpApiLiveFeed` speaks the Pinnodds frames from the store's live Pinnacle rows, so the engine's live lane can run on a REAL Pinnacle price (`PinnFeedChoice.SHARPAPI`).
- **Closing lines, usage, health, SharpAPI's +EV at Novig:** journaled on the engine for the CLV studies; `requests_today` feeds the usage meter.
- Switch: Settings › APIs › SharpAPI (`gates.useSharpApi`), key sent to GitHub as `SHARPAPI_API_KEY`. Off = never called.
